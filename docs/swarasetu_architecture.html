SYSTEM ARCHITECTURE SPECIFICATION

SwaraSetu End-to-End System Topology

Offline-first, voice-native triage platform bridging last-mile healthcare in rural India. Features a deterministic WHO IMCI clinical decision engine, dual-tier Sarvam AI cloud & edge STT, and dynamic ASHA worker dispatching.

1. Clinical Safety & IMCI Engine

Zero LLMs in the clinical decision path. 100% deterministic Python WHO IMCI implementation.

  • Deterministic Rule Execution: Evaluates 5 symptom clusters (General Danger Signs, Fever, Respiratory, Diarrhoea, Maternal).
  • Strict Auditability: Identical input payload produces identical risk output (1: Self-Care, 2: ASHA Dispatch, 3: Emergency PHC Referral).
  • Zero Hallucination: NLP/NER parsing failures soft-degrade to clarification prompts without fabricating default numbers.

2. Dual-Tier Deployment Architecture

Seamless operation across cloud-connected WhatsApp and 100% media-dark offline rural villages.

  • Tier 1 (WhatsApp/IVRS): Sarvam AI Cloud ASR & Bulbul:v2 TTS over Twilio webhooks with HMAC-SHA1 validation.
  • Tier 2 (CHW Tablet PWA): ONNX Runtime Web (WASM/WebGPU) executing quantized 4-bit Indic-Seamless speech model on-device.
  • Tier 3 (Legacy 2GB Devices): Touch-to-Hear visual form UI fallback + local JS IMCI engine (triageLocal.ts).

3. Data Persistence & Outbox Sync

Reliable offline queueing and spatial auto-routing for critical emergency presentations.

  • IndexedDB Outbox: Offline tablet cases stored in swarasetu-outbox with client-generated UUIDs.
  • Idempotent Batch Flush: Auto-flushes to POST /api/v1/sync/cases upon network recovery; backend deduplicates UUIDs.
  • Spatial PHC Routing: Haversine distance math routes Score 3 emergency cases to nearest open Primary Health Centre.
